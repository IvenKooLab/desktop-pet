Comi Pet v2.0.1 修复 v2.0.0 中"DSH 界面内"显示切换在 DSH 桌面应用上完全失效的问题。

### 本版修复

- DSH 桌面应用（0.2.1-rc.3 宿主）里，适配器路由对每个请求都抛 `cannot get property "webRuntime" without inject`：cordis 服务代理不允许读取未声明注入的服务，可选链拦不住代理 getter 的异常，宿主把异常吞成空 body 的 400——页面无法认领显示租约，桌宠总在 6 秒后回桌面。现在读取失败时安全回退空数组（本机 loopback 本来就放行）。
- 适配器 handler 加了异常守卫：出错时返回 500 带原因并落盘，不再出现不可诊断的空 400。

### 升级

- 替换程序并重启一次 DSH 桌面应用；适配器（comi-bridge）随本版更新。
- 数据目录与配置完全沿用 v2.0.0 的规则（旧 `~/.iven-pet` 自动识别，无需迁移）。

**English:** v2.0.1 fixes the embedded-DSH display handoff introduced broken in v2.0.0 on the DSH desktop app (0.2.1-rc.3 host): every adapter request threw because the cordis service proxy rejects reads of non-injected services, and the host swallowed the error into a bare 400, so the web page could never claim the display lease. The adapter now falls back safely and returns diagnosable errors. Swap the app, restart DSH once; the comi-bridge adapter ships with this release.
