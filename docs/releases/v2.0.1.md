## Changelog

v2.0.1 fixes the embedded-DSH display handoff that v2.0.0 broke on the DSH desktop application.

### Downloads

| File | Platform | How to run |
| --- | --- | --- |
| `ComiPet-v2.0.1-windows-x64.zip` | Windows x64 | Unzip and run `ComiPet.exe`; no Python needed |
| `ComiPet-v2.0.1-macos-universal.zip` | macOS 13+, Apple Silicon / Intel | Unzip and open `ComiPet.app`; no Python or compiler needed |
| `SHA256SUMS.txt` | All | SHA-256 checksums for both archives |

The macOS build is ad-hoc signed and not notarized, so Gatekeeper may warn about an unidentified developer: right-click the app and choose Open, or run `xattr -d com.apple.quarantine ComiPet.app`. You can also build from source following the README.

### What's fixed

- On the DSH desktop application (0.2.1-rc.3 host) every adapter request threw `cannot get property "webRuntime" without inject`: the cordis service proxy refuses to read services that were not declared as injected, optional chaining cannot catch a throwing proxy getter, and the host swallowed the exception into a bare 400 with an empty body — so the page could never claim the display lease and the pet always fell back to the desktop after six seconds. The lookup now falls back to an empty list on failure (loopback is trusted anyway).
- The adapter handler is guarded: failures return a 500 with the reason and are written to a debug log instead of an undiagnosable empty 400.

### Upgrade

- Replace the app and restart the DSH desktop application once; the adapter (`comi-bridge`) ships with this release.
- Data directories and configuration follow the v2.0.0 rules unchanged (the legacy `~/.iven-pet` is detected automatically, nothing to migrate).

## 更新日志

Comi Pet v2.0.1 修复 v2.0.0 中"DSH 界面内"显示切换在 DSH 桌面应用上完全失效的问题。

### 本版修复

- DSH 桌面应用（0.2.1-rc.3 宿主）里，适配器路由对每个请求都抛 `cannot get property "webRuntime" without inject`：cordis 服务代理不允许读取未声明注入的服务，可选链拦不住代理 getter 的异常，宿主把异常吞成空 body 的 400——页面无法认领显示租约，桌宠总在 6 秒后回桌面。现在读取失败时安全回退空数组（本机 loopback 本来就放行）。
- 适配器 handler 加了异常守卫：出错时返回 500 带原因并落盘，不再出现不可诊断的空 400。

### 升级

- 替换程序并重启一次 DSH 桌面应用；适配器（comi-bridge）随本版更新。
- 数据目录与配置完全沿用 v2.0.0 的规则（旧 `~/.iven-pet` 自动识别，无需迁移）。

**English:** v2.0.1 fixes the embedded-DSH display handoff introduced broken in v2.0.0 on the DSH desktop app (0.2.1-rc.3 host): every adapter request threw because the cordis service proxy rejects reads of non-injected services, and the host swallowed the error into a bare 400, so the web page could never claim the display lease. The adapter now falls back safely and returns diagnosable errors. Swap the app, restart DSH once; the comi-bridge adapter ships with this release.
